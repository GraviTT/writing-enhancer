# v2 요구사항과 검증 기준

이 문서는 구현 완료 여부를 기능별로 판단하기 위한 기준이다. 단순히 버튼이 존재하는 것만으로 완료로 보지 않고, 저장·복원·삭제·권한 실패까지 실제 동작해야 한다.

## 공통

### 상황 안내

- 입력 화면에서 본문과 구분된 짧은 상황 입력란을 제공한다.
- 비워도 기존의 즉시 강화 흐름이 그대로 동작한다.
- 값이 있으면 모든 최초 강화·재강화·질문 우선 요청에 포함된다.
- 임시 저장과 히스토리에도 함께 보존된다.

### 첨부

- 파일과 이미지를 선택해 첨부하고, 전송 전에 목록·종류·제거 동작을 확인할 수 있다.
- 크기·개수·지원 형식 제한과 이해 가능한 오류 메시지가 있다.
- 이미지는 모델의 이미지 입력으로, 텍스트 파일은 안전하게 추출한 제한 길이 텍스트로 전달한다.
- 첨부 내용은 시스템 지시가 아닌 참고 데이터로 경계를 표시한다.

### 화면 캡처

- 캡처 직전에 강화기 UI를 숨긴다.
- UI가 실제로 숨은 뒤 화면을 캡처하고, 성공·취소·오류 뒤에 UI를 복원한다.
- 결과 이미지는 일반 첨부와 동일하게 미리보기·삭제할 수 있다.
- 플랫폼 권한이 거부되어도 작성 내용은 유지된다.

### 알아맞춰 봐

- 기본 `완성하기` 흐름과 별개의 보조 행동이다.
- 누르면 AI가 완성문 대신 가장 영향이 큰 질문 하나부터 시작한다.
- 사용자는 짧거나 불완전하게 답할 수 있고 `알아서`도 사용할 수 있다.
- 답을 받은 뒤 완성문을 만들며 무한 질문 상태에 빠지지 않는다.

### 히스토리와 버전

- 이전 작업을 최신순의 간단한 목록으로 확인한다.
- 항목을 열면 상황·입력·최종 결과·버전을 복원한다.
- 각 항목을 개별 삭제할 수 있다.
- 재강화할 때 결과 버전이 추가되고, 이전·다음 버전으로 되돌릴 수 있다.
- 보존 개수 상한과 오래된 항목 정리가 있다.

### 임시 저장

- 본문·상황·후속 답변이 입력 중 자동 저장된다.
- 앱/패널을 닫았다가 다시 열어도 복원된다.
- 새 글 시작과 성공적인 작업 완료 시 명시적으로 정리할 수 있다.

### 음성 입력

- 본문과 후속 답변에 음성 입력을 시작·중지할 수 있다.
- 인식 중 상태가 보이며 기존 텍스트를 덮어쓰지 않고 이어 붙인다.
- 권한 거부·지원 불가·인식 실패를 처리하고 작성 내용을 보존한다.

### 복사 문구

- 모든 사용자 화면에서 주요 완료 행동은 `강화한 글 복사`로 표시한다.

### 기억 편집

- 기억 목록에서 값과 적용 범위를 확인한다.
- 항목별 수정·삭제가 가능하다.
- 수정 내용은 이후 검색과 프롬프트에 즉시 반영된다.
- 민감정보로 수정하려는 경우 저장을 거부한다.

## Windows

### 창 이동과 배치 모드

- 접힌 손잡이와 펼친 패널 모두 드래그할 수 있다.
- 드래그 이동 중에는 시작 시점의 너비·높이를 유지하며, 크기는 우하단 전용
  손잡이로 조절할 때만 변경한다.
- 설정·기록·기억 팝업 제목도 드래그할 수 있다.
- 고정 모드에서는 좌·우 가장자리를 선택하고 세로 위치를 기억한다.
- 자유 이동 모드에서는 다시 잡을 가장자리를 남긴 채 일부를 화면 밖에 둘 수 있다.
- 모니터·해상도 변경 후에도 창을 다시 잡을 수 있다.

### 표시 설정

- 투명도를 조절하면 현재 창에 즉시 반영되고 다음 실행에도 유지된다.
- 글자 크기와 창 크기를 조절하면 입력·결과·설정 화면이 잘리지 않는다.
- 우하단 손잡이로 창 크기를 조절하며 380~680 × 560~920 범위로 제한한다.
- 상황과 파일·현재 화면·말하기는 첫 화면에서 접어 둔다.
- 5단계 강화 범위, 원문·결과 기록, 기억 추가 승인과 비활성화를 제공한다.
- 첫 완성 직후에는 예상 글 유형·주제·목적에 맞춘 추가 다듬기 허용을 묻고,
  두 번째 질문부터 기존 후속 질문 방식을 사용한다.
- 현재 상황과 직접 지정한 문체·구조·대상·목적을 기본 강화 규칙보다 우선하고,
  구체적인 줄·문장·문단·배수·글자 수 요구는 강화 범위보다 먼저 적용한다.
- 이름·인물·날짜·시간·금액·숫자·장소·관계·약속·확정·부정 등 사실은 원문,
  상황, 사용자 답변과 사용자가 첨부한 자료에 명시된 범위 밖에서 추정하지 않는다.
- 메인 화면의 재강화는 이전 출력·질문·AI 추론을 제외하고 원문과 기존 설정으로
  새 버전을 만든다. 결과에 대한 후속 요구만 현재 결과에서 이어서 다듬는다.

### 사이드 채팅 베타

- 글 강화기와 별도 창으로 연다.
- 동일 API 키와 공급자 폴백을 사용하되 전용 채팅 프롬프트와 별도 대화 파일을 사용한다.
- 현재 작성 중인 상황·원문·결과·후속 요구·강화 범위를 인식한다.
- 글 강화기 기능을 설명하고, 명시적 실행 요청은 구조화된 기능 명령으로 연결한다.
- 권한·파일 선택·기억 승인처럼 사용자 직접 조작이 필요한 동작은 자동 승인하지 않는다.
- 글 히스토리와 기억을 임의로 검색·변경하거나 채팅 내용을 기억에 추가하지 않는다.
- 텍스트 대화, 새 대화, 최근 메시지 복원, 창 이동·크기 조절을 지원한다.
- 사용자 메시지를 수정하면 그 지점 이후 대화를 제거하고 즉시 다시 응답한다.
- 새 대화는 내부 확인 팝업을 사용하며 초기화 직후 창·웹 콘텐츠·입력칸
  포커스를 복원해 별도 조치 없이 바로 입력할 수 있다.
- 사용자 메시지의 수정 버튼은 말풍선 왼쪽에, AI 답변 복사 버튼은 말풍선
  오른쪽에 둔다. 복사는 해당 답변만 클립보드에 기록한다.
- 최신 정보·사실 확인·비교·추천·정책 요청에는 OpenAI Web Search 또는 Gemini
  Google Search를 모델이 자동 선택해 사용하고, 글쓰기·앱 기능 요청에는 검색을
  요구하지 않는다.
- 사용자가 검색·최신 정보·뉴스·가격·정책·비교·추천·사실 확인을 명시한 경우와
  현재 화면이 포함된 경우에는 기본적으로 웹 검색을 필수로 하며, 공급자 근거가
  없으면 검색 성공으로 표시하지 않는다. 명시적 검색 금지는 이 기본값보다 우선한다.
- 단순 글쓰기·앱 기능·현재 작성 중인 글에 관한 요청은 로컬 문맥으로 처리한다.
  사용자가 검색을 명시적으로 금지한 경우에는 OpenAI·Gemini 요청 모두에서 검색
  도구를 생략하며, 이 금지는 후속 검색 강제 신호보다 우선한다.
- 복합 질문은 관련 하위 주제를 나누어 여러 검색 결과를 교차 확인하고, 단순 결과
  나열이 아니라 직접 답변·핵심 근거·비교 또는 다음 행동으로 종합한다.
- 검색 답변에는 같은 문맥에서 이어갈 수 있는 짧은 후속 탐색 질문을 최대 3개
  제공하며, 사용자가 누르면 새 입력을 다시 작성하지 않고 후속 검색을 시작한다.
- 검색 출처는 공급자 메타데이터에서만 가져와 중복 제거 후 최대 6개 보관하며,
  사용자에게 제목과 안전한 `http`·`https` 링크로 표시한다.
- 사이드 채팅에서 사용자가 `현재 화면`을 직접 요청하면 앱 UI를 잠시 숨긴 뒤 현재
  디스플레이 한 장을 촬영한다. Android는 시스템 MediaProjection 동의를 거친다.
- 캡처 이미지는 다음 질문 한 번에만 포함하고 글 첨부, 사이드 채팅 메시지,
  기억에 저장하지 않는다. 성공·실패·취소 뒤에는 임시 이미지와 대기 상태를 정리한다.
- 화면 검색은 이미지와 질문을 같은 멀티모달 요청으로 보내고 기본적으로 웹 검색도
  활성화한다. 단, 사용자가 검색을 명시적으로 금지하면 웹 도구 없이 화면만 분석한다.
  화면에서 실제로 보이는 내용과 웹 근거를 구분하며 보이지 않는 사실을 추정하지 않는다.
- 실제 검색 도구가 실행됐거나 검색 출처 또는 현재 화면이 포함된 응답의 기능 action은 항상 `none`으로 정규화해
  웹 문서나 화면의 간접 프롬프트가 원문·결과·초안을 변경하지 못하게 한다.
- 검색·화면에서 파생된 답변에는 외부 자료 표시를 메시지 메타데이터로 유지한다.
  외부 답변을 참조하는 후속 action은 차단한다. 외부 답변과 독립된 설정·현재 글
  명령 또는 사용자가 충분한 새 텍스트를 직접 입력한 요청은 외부 대화를 잘라낸 뒤
  일반 로컬 action을 허용한다.
- 화면 이미지를 보낸 공급자가 실패하더라도 같은 이미지를 다른 공급자에게 자동
  재전송하지 않는다. 이미지는 폐기하고 사용자가 다시 선택하게 한다.
- 재강화 명령은 원문과 기존 설정으로 새 결과를 만들고, 결과 반영 명령은 현재
  버전을 덮어쓰지 않고 새 버전으로 보존한다.

## Android

### 자동 확장 입력

- 본문과 후속 답변 입력창이 줄 수에 따라 자연스럽게 커진다.
- 지정한 최대 높이 이후에는 내부 스크롤을 사용한다.
- 키보드가 열린 상태에서도 버튼과 현재 입력 줄에 접근할 수 있다.

### 버블

- 설정한 크기가 즉시 반영되고 다음 실행에도 유지된다.
- 기본적으로 드래그한 위치에 그대로 머물며 가장자리로 강제 스냅하지 않는다.
- 길게 누르거나 일정 시간 드래그하면 하단 삭제 영역이 나타난다.
- 삭제 영역에 놓으면 서비스가 종료되고, 그 외 위치에 놓으면 삭제 영역이 사라진다.

### 접기

- X 버튼, Android 뒤로가기, 패널 바깥 영역 터치가 모두 패널을 닫고 버블을 복원한다.
- 접기 동작은 현재 입력과 임시 저장을 지우지 않는다.

### 반응형 편집과 생성 상태

- 원문의 축소 편집 메뉴는 같은 버튼 재터치로 접고, 뒤로가기는 메뉴 상태를 바꾸지 않는다.
- 상황·추가 질문에는 붙여넣기·되돌리기·복사·잘라내기·전체 선택 메뉴를
  노출하지 않으며 추가 질문에는 음성 입력도 노출하지 않는다.
- `다시 강화`·`반영하기`·결과 제안의 `예` 실행 시 누른 버튼 자체를 생성 상태로 바꾸고
  완료 전 중복 생성 요청을 차단하며 별도 로딩 아이콘은 표시하지 않는다.
- 창 크기에 따라 여백·입력 줄 수·결과 높이를 조절하고, 주요 동작은 고정 영역에
  유지해 작은 창에서도 사라지거나 전체 화면 스크롤을 만들지 않는다.
- 상단 로고와 메뉴는 콘텐츠 스크롤 및 창 크기 변경과 분리해 화면에 고정한다.
- 결과 버전 줄 오른쪽에 이전·다음 아이콘을 두고, 원문 보기 바로 왼쪽에 작은
  재강화 아이콘을 둔다.
- 재강화는 현재 결과·질문·추론을 제외하고 기존 설정과 원문을 기준으로 요청한다.
  결과의 `예`와 `반영하기`는 현재 결과를 기준으로 새 결과를 요청한다.
- 직접 요구가 입력되면 AI 제안 영역을 감광하고 `예`를 비활성화한다.
- 직접 지정한 문체·구조는 기본 강화 규칙보다 우선하고, 줄·문장·문단·배수·글자
  수처럼 구체적인 분량은 슬라이더 목표보다 우선한다. 사실 안전 규칙은 항상
  최우선으로 적용한다.

### PC 선반영 기능의 모바일 적용

- 첫 완성 뒤에는 글 유형·주제·목적을 예상해 해당 목적에 맞춘 추가 다듬기
  허용을 묻고, 후속 입력 안내를 `아니면 다른 요구 사항 입력`으로 표시한다.
- 사이드 채팅은 별도 오버레이를 겹치지 않고 현재 팝업 안의 독립 화면으로 열며,
  진입 버튼은 모든 글 강화기 화면의 최상단 `기록` 바로 오른쪽에 둔다.
- 현재 상황·원문·결과·후속 요구·강화 범위·버전·첨부 이름을 채팅 문맥에 포함한다.
- 채팅 기록은 글 기록·기억과 분리해 암호화하고 최근 60개만 보관하며, AI에는
  최근 20개·최대 2만4천 자만 전달한다.
- 사용자 메시지를 수정하면 해당 지점 이후를 제거하고 수정문부터 즉시 재응답한다.
- 새 대화 뒤 입력창은 즉시 다시 사용할 수 있어야 하며 키보드는 직접 탭할 때만 연다.
- `새 채팅` 버튼은 사이드 채팅 최상단 `글로` 바로 왼쪽에 둔다. 사용자 메시지의
  `수정`은 말풍선 왼쪽, AI 답변의 `복사`는 말풍선 오른쪽에 둔다.
- 사이드 채팅에서 X로 접으면 다음 버블 터치 때 채팅을 복원하고, 글 강화기에서
  X로 접으면 다음 버블 터치 때 글 강화기를 복원한다.
- 채팅의 재강화는 현재 결과를 제외하고 원문과 기존 설정으로 새 버전을 만들며,
  결과 반영도 현재 버전을 덮어쓰지 않고 새 버전으로 보존한다.
- 명시적인 기능 실행 요청만 글 강화기 동작으로 연결하고 권한·첨부·음성·기억
  승인은 사용자를 대신해 실행하지 않는다.
