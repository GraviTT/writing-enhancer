# 최종 검증 보고서

## 결론

Windows 휴대용 앱과 Android 플로팅 버블 앱을 최종 소스에서 다시 빌드했다.
자동 테스트, 정적 검사, Windows 화면 QA, 배포 파일 무결성 검사를 통과했다.

| Android v0.4.2 | `android/WritingEnhancer-debug.apk` | 1,217,932 bytes | `AB01D2FBF581EC2EEF42872A7AA65603322ACCDBACA06D4ACB8317D10D8F1149` |

## 공통 기능

- 상황 안내, 이미지·PDF·텍스트 첨부, 현재 화면 첨부
- 기본 완성 우선 흐름과 선택형 `알아맞춰 봐` 단일 질문 흐름
- 히스토리 선택 삭제, 재강화, 이전·다음 결과 탐색
- 본문·상황·후속 답변·질문 상태 임시 저장과 복원
- 본문과 후속 답변 음성 입력
- `강화한 글 복사`
- 기억 목록 확인·수정·삭제, 중복 병합, 민감정보 저장 거부

공통 TypeScript 계약·정책 테스트는 typecheck와 함께 39/39 통과했다.

## Windows

- 접힌 손잡이와 펼친 패널을 모두 드래그할 수 있다.
- 이동 시작 크기를 고정해 드래그 중 손잡이와 패널의 크기가 변하지 않으며,
  크기 변경은 우하단 전용 손잡이에서만 일어난다.
- 상황과 파일·화면·말하기 도구는 첫 화면에서 접어 두고 필요할 때만 연다.
- 강화 범위는 중앙 `원문 충실`과 좌우 45~200% 목표 글자 수를 실제 프롬프트에 반영한다.
- 기록 목록과 열린 결과에서 최초 원문과 결과를 함께 확인한다.
- 기억 후보는 승인 뒤에만 저장하고 설정에서 새 기억 추가를 비활성화할 수 있다.
- 가장자리 고정 또는 자유 이동, 좌우 배치, 55~100% 투명도, 글자 크기,
  창 크기를 저장한다.
- 패널과 팝업 제목을 드래그하고 우하단에서 크기를 조절하며, 자유 이동에서는
  다시 잡을 가장자리를 남긴 채 일부를 화면 밖에 둘 수 있다.
- 모니터 추가·제거·배율 변경 때 창을 다시 잡을 수 있는 위치로 보정한다.
- 화면 촬영 때 창을 숨기고, 성공·실패 뒤 원래 표시 상태를 복원한다.
- 단축키가 점유되어도 트레이와 화면 손잡이로 계속 실행한다.
- 첨부의 선언 형식뿐 아니라 PNG·JPEG·WebP·GIF·PDF 실제 헤더를 검사한다.
- `사이드 채팅` 베타는 별도 창, 전용 프롬프트, 별도 로컬 대화 파일을 사용한다.
- 현재 상황·원문·결과·후속 요구·강화 범위를 인식하며 사용자가 명시적으로
  요청한 글 강화기 동작을 구조화된 기능 명령으로 연결한다.
- 채팅은 글 기억을 읽거나 자동 추가하지 않으며, 권한·파일 선택·기억 승인이
  필요한 기능은 관련 화면까지만 연결한다.
- 최근 60개 메시지와 창 위치를 복원하며 새 대화는 채팅 기록만 지운다.
- 모델 요청에는 최근 20개·최대 2만4천 자까지만 사용한다.
- 첫 완성 질문은 예상 글 유형·주제·목적에 맞춰 더 다듬어도 되는지 묻고,
  두 번째 질문부터 기존 후속 질문 흐름을 유지한다.
- 직접 문체·구조·목적과 구체적인 분량 요구를 기본 규칙·강화 범위보다 먼저
  적용하고, 사실의 출처를 원문·상황·사용자 답변·사용자 첨부로 제한한다.
- 메인 화면과 사이드 채팅의 재강화는 이전 출력 없이 원문과 기존 설정으로 새
  버전을 만들며, 채팅의 결과 반영 역시 기존 버전을 덮어쓰지 않는다.
- 사용자 메시지 수정 시 해당 지점 이후 대화를 제거하고 수정문부터 다시 답한다.
- 사이드 채팅의 새 대화는 내부 확인 팝업을 사용하며 초기화 직후 입력칸이
  다시 활성화되어 즉시 입력할 수 있다.
- `새 채팅`은 창 최상단에 두고, 사용자 메시지의 `수정`은 말풍선 왼쪽에 배치한다.
  AI 답변의 `복사`는 말풍선 오른쪽에 배치하며 전용 IPC로 클립보드에 복사한다.
- 최신 정보·사실 확인·비교·추천·정책 요청에는 OpenAI `web_search` 또는 Gemini
  `googleSearch`를 자동 제공한다. 답변은 결론을 먼저 종합하고, 공급자가 반환한
  출처만 최대 6개 표시하며 검증된 `http`·`https` 주소만 외부 브라우저로 연다.
- 복합 질문은 2~5개의 하위 주제와 비교 기준을 검색하도록 요청하고 OpenAI 검색
  문맥을 `high`, 최대 도구 호출을 8회로 설정한다. 검색 답변의 후속 탐색 질문은
  최대 3개만 표시하고 누르면 즉시 다음 검색을 시작한다.
- 명확한 한·영 검색 의도와 현재 화면은 기본적으로 실제 출처를 필수로 한다. 출처가
  없으면 일반 검색은 다음 공급자로 폴백하고, 화면은 개인정보 보호를 위해 다른
  공급자에 재전송하지 않고 실패 처리한다. 명시적 검색 금지 시에는 화면만 분석한다.
- 실제 검색 도구가 실행됐거나 화면·검색 출처가 있는 응답의 글 강화기 action은 AI 계층과 메인 프로세스에서
  이중 차단한다. 외부 자료 표시는 후속 턴에도 유지해 우회 action을 막는다. Alt+F4를
  포함한 닫기, 성공·실패·취소 뒤 화면 대기 상태를 폐기한다. 외부 답변과 독립된
  로컬 명령·직접 입력은 외부 대화를 잘라 정상 처리한다.
- 화면은 종횡비를 유지해 최대 1920×1200으로 만들고 8MB를 넘으면 단계적으로
  축소한다. 출처·후속 질문·화면 상태 UI도 작은 글자 설정에서 읽히도록 보강했다.

Windows 테스트는 98/98 통과했다. `qa/v3-*.png` 화면 10종을 생성해 입력,
접힌/펼친 도구, 질문 우선, 결과별 강화 범위, 기억 승인, 원문·결과 히스토리,

오른쪽 배치를 확인했고,
`qa/v4-02-first-follow-up.png`에서 개선된 첫 질문과
`아니면 다른 요구 사항 입력` 안내를 확인했다.
`qa/v4-03-side-chat-edit.png`에서 현재 글 연동 표시와 사용자 메시지 인라인

  강화 범위 기능 명령 연동 확인
- 화면 촬영 중 숨김과 복원
- 임시 추출 폴더 정리

## Android

- 두 입력창은 지정한 최대 줄 수까지 커지고 이후 내부 스크롤한다.
- 버블 크기를 저장하며 화면 안의 원하는 위치에 자유롭게 놓을 수 있다.
- 450ms 길게 누르면 하단 종료 영역이 나타나고, 그곳에 놓으면 서비스를 종료한다.
- 패널·설정을 열 때 키보드를 자동 표시하지 않고 입력칸을 직접 누를 때만 표시한다.
- IME 표시 높이와 창 resize를 함께 계산해 입력칸과 주요 동작까지 스크롤할 수 있다.
- 뒤로가기는 편집기·기록·질문 상태를 먼저 닫고 최상위 화면에서만 패널을 버블로
  접으며 서비스나 버블을 종료하지 않는다.
- 입력창은 손을 뗀 뒤 touch slop 안의 동작만 탭으로 판정해 키보드를 열고,
  스와이프·스크롤·선택 제스처에는 입력창을 강제로 올리지 않는다.
- 길게 누르기는 Android 기본 선택 동작을 사용해 선택을 유지한다. 편집 기능은
  `⋯` 버튼 또는 커서 핸들에서만 인라인 메뉴로 펼친다.
- 원문 편집 메뉴는 같은 `⋯` 버튼을 다시 눌러 접을 수 있고, 뒤로가기로 키보드를
  닫아도 메뉴의 펼침 상태가 유지된다.
- 상황과 추가 질문 입력에는 인라인 편집 기능을 노출하지 않으며, 추가 질문의
  별도 음성 입력 버튼도 제거했다.
- `다시 강화`·`반영하기`·결과 제안의 `예`는 누른 버튼 안에 생성 상태를 표시하고
  같은 화면의 생성 버튼을 모두 잠근다. 완료·실패 뒤 기존 상태를 복원하며 별도
  로딩 아이콘은 사용하지 않는다.
- 상단 로고·메뉴, 스크롤 콘텐츠, 하단 주요 동작을 분리했다. 창 크기에 따라
  여백·입력 줄 수·결과 최소 높이를 조절하고 최소 창에서도 상단과 핵심 버튼을
  고정 노출한다.
- 결과 버전 줄 오른쪽에 이전·다음 아이콘을, 원문 보기 바로 왼쪽에 작은 `↻`을
  배치했다. `↻`은 현재 결과·질문·추론 없이 원문과 기존 설정으로 요청하고,
  `예`·`반영하기`는 현재 결과를 기준으로 요청한다.
- 직접 요구가 입력되면 AI 제안과 `예`가 감광되고 `예`는 비활성화된다.
- 직접 문체·구조 요구와 구체적인 줄·문장·문단·배수·글자 수 요구를 기본 규칙과
  슬라이더 분량보다 우선하도록 프롬프트를 분리했고, 사실 안전을 절대 조건으로
  유지했다.
- 첫 완성 질문은 완성 글의 유형·주제·목적을 예상해 그 목적에 맞춰 더 다듬을지
  묻고, 두 번째부터는 이번 수정의 추천 판단과 다음 수정 방향을 묻는다. 후속 입력
  안내는 `아니면 다른 요구 사항 입력`으로 표시한다.
- PC에서 먼저 제공한 사이드 채팅을 모바일에서는 같은 오버레이 안의 독립 화면으로
  변형했다. 모든 글 강화기 화면의 최상단 `기록` 바로 오른쪽 `β`에서 열고,
  접힌 도구 메뉴에서는 기존 채팅 버튼을 제거했다.
- 사이드 채팅은 현재 원문·상황·결과·후속 요구·강화 범위·버전·첨부 이름을
  인식하고 명시적인 기능 명령을 글 강화기 화면과 실행에 연결한다.
- 채팅 기록은 글 히스토리·기억과 분리해 암호화하고 최근 60개만 보관하며 AI에는
  최근 20개·최대 2만4천 자만 전달한다.
- 사용자 메시지를 수정하면 그 지점 이후를 제거하고 수정문부터 재응답한다.
  최상단 `새 채팅`은 `글로` 왼쪽에 있으며 새 채팅 뒤 입력칸은 즉시 다시 사용할
  수 있고 키보드는 직접 탭할 때만 연다.
- 사용자 메시지의 `수정`은 말풍선 왼쪽에, AI 답변의 `복사`는 말풍선 오른쪽에
  배치해 답변을 Android 클립보드로 복사한다.
- 채팅 재강화는 현재 결과를 제외하고 원문과 기존 설정으로 새 버전을 만들며,
  결과 반영 역시 기존 결과를 덮어쓰지 않는 새 버전으로 저장한다.
- 사이드 채팅에서 X로 접으면 다음 버블 터치 때 채팅을, 글 강화기에서 X로
  접으면 다음 버블 터치 때 글 강화기를 복원한다. 마지막 화면은 로컬 상태로
  저장해 서비스 재시작 뒤에도 유지한다.
- 최신 외부 정보가 필요한 사이드 채팅 요청에는 공급자 내장 웹 검색을 자동
  제공하고, 검색 메타데이터의 출처만 최대 6개 표시해 기본 브라우저로 연다.
- 복합 질문을 2~4개 판단 축으로 나눠 검색하도록 요청하고, 명확한 한·영 검색
  의도와 현재 화면은 기본적으로 실제 출처가 없으면 성공 처리하지 않는다. 명시적
  검색 금지 시에는 화면만 분석한다. 검색 답변 아래의
  후속 질문은 최대 3개이며 탭하면 키보드를 강제로 열지 않고 바로 재검색한다.
- 사이드 채팅의 `현재 화면`은 MediaProjection 동의 뒤 한 장만 다음 질문에 쓰고
  성공·실패 후 임시 파일을 삭제한다. 글 첨부·채팅 기록·기억에는 저장하지 않으며
  첫 공급자 실패 시 다른 공급자에게 화면을 재전송하지 않는다.
- 실제 검색 도구가 실행됐거나 검색 출처·화면이 포함된 응답의 기능 action은 AI 처리와 UI 실행 경계에서
  다시 `none`으로 만들어 외부 콘텐츠가 글 상태를 변경하지 못하게 한다. 외부 자료
  표시는 저장·복원되어 후속 턴의 우회 action도 차단한다. 독립적인 로컬 명령·직접
  입력은 외부 대화를 잘라 정상 처리한다.
- 선택 범위와 여러 줄 한글을 보존하는 붙여넣기를 지원하고, 커스텀 처리가
  불가능하면 Android 기본 붙여넣기로 안전하게 위임한다.
- 강화 범위는 왼쪽 `핵심 요약·간결 정리`, 중앙 `원문 충실`, 오른쪽
  `내용 보완·풍부하게 확장`으로 정의하고 45~200% 비율과 요청별 목표 글자 수를
  프롬프트에 명시한다. 결과 버전에 사용 단계를 저장하고 이동 때 함께 복원한다.
- 상황 입력과 파일·현재 화면·말하기 도구는 첫 화면에서 접어 두고 필요할 때만 연다.
- 기록 카드와 열린 결과에서 최초 원문과 최종 결과를 함께 확인할 수 있다.
- 기억 후보는 로컬 저장 전에 `기억에 추가` 또는 `추가 안 함`을 반드시 고르게 하며,
  설정에서 새 기억 추가를 비활성화할 수 있다.
- 주요 오버레이와 설정 팝업은 상단 드래그 이동, 우하단 크기 조절, 부분 화면 밖
  배치와 55~100% 투명도 저장을 지원한다.
- AI 요청 중 다른 기록이나 입력으로 이동하면 늦게 도착한 응답을 폐기해 결과가
  다른 작업에 섞이지 않게 한다.
- 질문 우선 상태의 질문·추론·답과 일반 후속 답변·선택 버전을 암호화해 복원한다.
- 화면 촬영은 오버레이를 숨기고 한 장만 저장한 뒤 MediaProjection 서비스를 끝낸다.
- 첨부 제거·새 글·히스토리 삭제 및 앱 시작 때 참조되지 않는 내부 첨부를 정리한다.
- 이미지·PDF 실제 헤더, 안전한 파일명, 최종 직렬화 요청 크기를 검사한다.

62개 논리 단위 테스트가 Gradle debug 테스트 작업에서 통과했다.
Android lint XML 이슈는 0개이고 `assembleDebug`가 성공했다. APK는 signer 1의
APK Signature Scheme v2 서명으로 검증됐다.

연결된 Samsung Android 실기기와 Smart Keyboard Pro에서 오버레이를 열고,

## 보안과 데이터 최소화

- API 키를 소스에 넣지 않는다.
- Windows는 Electron `safeStorage`, Android는 Keystore 기반 AES-GCM 저장소를 사용한다.
- 두 공급자 요청에 `store: false`를 명시한다.
- Gemini 키는 URL이 아니라 `x-goog-api-key` 헤더로 전송한다.
- 첨부 텍스트는 비신뢰 데이터 경계 안에 넣고 길이·개수·크기를 제한한다.
- 기억은 최대 50개, 요청당 최대 5개만 사용하며 모델의 근거 없는 장기 기억 주장을 강등한다.
- 자격증명, 금융, 신분, 연락처, 의료 정보가 포함된 기억 저장·수정을 차단한다.

## 환경상 남은 실기 검증

- 빌드 머신 환경 변수에는 API 키를 두지 않았다. 연결된 실기기에 저장된 키로
  강화와 사이드 채팅 실호출을 확인했으며, 공급자 자동 폴백은 모의 응답으로 검증했다.
- 이번 변경의 필수 검색 분류·출처 추출·URL 안전성·후속 검색·화면 비영구화·
  단일 공급자 전송·간접 기능 명령 차단은 자동 테스트로 검증했다. 현재 Android
  기기가 연결되지 않았고 별도 Windows 검증 프로세스에서 암호화된 API 키를 읽을 수
  없어 실제 웹 검색 및 화면 검색 네트워크 호출은 재검증하지 못했다.
- Android 음성 인식과 MediaProjection 권한 흐름은 실기기에서 수동 검증하지 않았다.
- Windows 실제 마이크 음성 인식과 물리적 다중 모니터 hot-plug은 자동 테스트만
  수행했으며 해당 하드웨어를 사용한 수동 검증은 하지 못했다.
- Windows ZIP은 설치 프로그램이 아닌 서명되지 않은 휴대용 빌드다.
- Android APK는 개발용 debug 서명 빌드이며 앱 스토어 배포용 release 서명본은 아니다.
