# v2 검증 기준

## 핵심 사용자 흐름

- 첫 화면에서 설명을 읽지 않아도 본문 입력 위치와 `완성하기`를 찾을 수 있다.
- 상황 입력은 선택 사항이며, 비워도 기존의 즉시 완성 흐름이 유지된다.
- 횡설수설한 입력에도 빈 결과나 설정 질문 대신 바로 쓸 수 있는 완성문을 먼저 제시한다.
- `알아맞춰 봐`를 명시적으로 누른 경우에만 AI가 가장 중요한 질문 하나를 먼저 한다.
- 사용자는 질문에 짧게 답하거나 `알아서`를 눌러 곧바로 완성문을 받을 수 있다.
- 모든 완료 버튼의 문구는 `강화한 글 복사`이며, 복사 뒤에도 히스토리에서 결과를 다시 찾을 수 있다.
- 설정 톱니는 찾을 수 있지만 기본 행동보다 눈에 띄지 않는다.

## 입력 보존과 복원

- 본문·상황·후속 답변은 입력 중 자동 저장된다.
- 앱이나 패널을 닫았다 다시 열어도 작성 중 내용이 복원된다.
- 패널 접기, 창 바깥 터치, Android 뒤로가기는 임시 저장을 지우지 않는다.
- 새 글 시작은 사용자가 명시적으로 선택할 때만 현재 초안을 정리한다.

## 첨부와 화면 캡처

- 지원 파일과 이미지를 선택하면 이름·형식·크기가 보이고 개별 제거할 수 있다.
- 파일 개수·개별 크기·전체 크기·지원 형식 제한을 넘으면 이해 가능한 오류가 표시된다.
- 이미지와 화면 캡처는 실제 모델의 이미지 입력으로 전달된다.
- 텍스트 참고 자료는 제한된 길이로 추출되며, 지시가 아닌 신뢰하지 않는 참고 데이터로 구분된다.
- 화면 캡처 직전 강화기 UI가 숨고, 캡처 성공·취소·오류 뒤 반드시 복원된다.
- 권한 거부와 취소 뒤에도 기존 입력과 첨부가 유지된다.

## 히스토리와 결과 버전

- 히스토리는 최신 작업부터 간단한 제목·미리보기·시간으로 표시된다.
- 작업을 열면 상황·원문·최종 결과·현재 버전이 복원된다.
- 작업별 삭제가 가능하고 다른 작업에는 영향을 주지 않는다.
- 재강화할 때 기존 결과를 덮어쓰지 않고 새 버전을 추가한다.
- 이전·다음 버전 이동이 가능하고 현재 버전 번호를 알 수 있다.
- 히스토리와 버전은 정해진 상한까지만 보존된다.

## 음성 입력

- 본문과 후속 답변에서 음성 입력을 시작·중지할 수 있다.
- 인식 중 상태가 눈에 보이며 인식 결과는 기존 텍스트 뒤에 이어 붙는다.
- 권한 거부·지원 불가·인식 실패 뒤에도 작성 내용은 유지된다.

## 기억

- 단일 입력에서 장기 기억을 과도하게 생성하지 않는다.
- AI가 스스로 보충한 내용과 일회성 세부사항을 기억하지 않는다.
- 같은 기억은 중복 생성하지 않고 병합한다.
- 다른 수신자·프로젝트의 기억이 섞이지 않는다.
- 현재 입력이 과거 기억과 충돌하면 현재 입력을 우선한다.
- 기억은 최대 50개, 요청당 최대 5개만 사용한다.
- 기억 목록에서 값과 범위를 확인하고 항목별 수정·삭제가 가능하다.
- 수정은 다음 검색과 프롬프트에 즉시 반영되며 민감정보 저장은 거부된다.

## 글 품질

- 사용자의 핵심 의도와 긍정·부정이 뒤집히지 않는다.
- 제공하지 않은 이름, 날짜, 금액, 약속을 만들어내지 않는다.
- 메신저·메일·요청·공지·프롬프트 등 의도된 형식을 자연스럽게 추론한다.
- “모르겠어”, “별로야”, “좀 세”, “알아서” 같은 불완전한 피드백을 처리한다.
- 맞춤법만 고치는 데 그치지 않고 바로 사용할 수 있는 글로 완성한다.

## 보안과 프라이버시

- API 키가 소스, 로그, 설정 평문 파일에 나타나지 않는다.
- 비밀번호·인증번호·금융·신분·의료 정보는 장기 기억에 저장되지 않는다.
- 대기 상태에서 화면, 마이크, 파일, 클립보드를 상시 수집하지 않는다.
- 화면 캡처와 음성 입력은 사용자가 누른 순간에만 권한을 요청한다.
- Android 오버레이 권한의 목적을 요청 전에 설명한다.
- 앱 종료 및 권한 해제 후 오버레이가 남지 않는다.

## Windows

- 패널이 항상 위에 유지되고 접힌 상태가 화면 작업을 방해하지 않는다.
- 접힌 손잡이와 펼친 헤더를 모두 드래그할 수 있다.
- 이동을 시작한 시점의 너비·높이를 고정해 드래그만으로 창이나 손잡이가 커지지 않는다.
- 설정·기록·기억 팝업 제목도 드래그할 수 있다.
- 가장자리 고정 모드에서 좌·우 위치와 세로 위치가 유지된다.
- 자유 이동 모드에서 다시 잡을 가장자리를 남긴 채 일부를 화면 밖에 둘 수 있다.
- 다중 모니터·해상도 변경 뒤에도 창을 다시 잡을 수 있다.
- 투명도·글자 크기·창 크기가 즉시 적용되고 다음 실행에도 유지된다.
- 우하단 손잡이로 창 크기를 조절할 수 있다.
- 상황·도구 기본 접기, 5단계 강화 범위, 원문·결과 기록, 기억 승인을 확인한다.
- 첫 완성 질문은 글 유형·주제·목적을 예상해 추가 다듬기 허용을 묻고, 두 번째
  질문부터 기존 후속 질문 흐름을 유지하는지 확인한다.
- 직접 문체·구조·목적과 구체적인 분량 요구가 기본 규칙·강화 범위보다 우선하고,
  사용자 제공 정보 밖의 사실을 생성하지 않도록 프롬프트 계약을 검사한다.
- 메인 화면과 사이드 채팅의 재강화가 현재 결과를 보내지 않고 원문 기준으로
  새 버전을 만들며, 채팅의 결과 반영도 기존 버전을 덮어쓰지 않는지 검사한다.
- 입력·설정·결과·히스토리·도구·기억 승인·질문 우선 상태의 QA 캡처가 존재한다.
- 사이드 채팅이 별도 창으로 열리고 채팅 기록은 별도 저장소를 사용하며 기억을
  읽거나 자동 추가하지 않는지 검사한다.
- 현재 상황·원문·결과·후속 요구·강화 범위가 사이드 채팅 프롬프트에 전달되고
  기능 명령이 메인 렌더러에 연결되는지 검사한다.
- 사용자 메시지 수정 시 해당 메시지 이후가 저장소와 화면에서 제거되고
  수정문 기준의 새 답변만 붙는지 검사한다.
- 새 대화는 네이티브 확인창을 사용하지 않으며, 초기화 직후 실제 네이티브
  텍스트 삽입이 입력칸에 들어가는지 검사한다.
- 사용자 메시지 왼쪽의 수정과 AI 답변 오른쪽의 복사 버튼을 확인하고, 복사 IPC가
  해당 답변만 클립보드에 쓰는지 검사한다.
- OpenAI 요청에는 `web_search`, Gemini 요청에는 `googleSearch`가 연결되고,
  사용자가 웹 검색을 직접 요청했거나 검색 버튼·후속 탐색을 누른 경우에만 검색을
  필수로 하며, 주제어·화면 첨부·글쓰기 요청(`검색 엔진 최적화 글`, `원문에서 오타 찾아줘`)은
  자동 판단으로 남는지 검사한다.
- 복합 검색 프롬프트가 하위 주제 분해·복수 검색·핵심 근거 교차 확인·결론 우선
  종합을 요구하고, 검색 답변의 후속 탐색 질문을 최대 3개로 제한하는지 검사한다.
- 공급자 메타데이터의 출처가 최대 6개로 정규화·중복 제거·저장되고, 위험한 URL은
  폐기되며 답변 아래의 출처 버튼만 안전한 외부 링크 열기로 이어지는지 검사한다.
- `현재 화면` 버튼은 메인 창과 채팅 창을 숨긴 뒤 현재 디스플레이를 촬영하고 원래
  표시·포커스 상태를 복원하는지 검사한다. 이미지는 다음 채팅 요청에만 포함하고
  글 첨부나 채팅 저장소에는 기록하지 않는다.
- 검색 금지가 없는 화면 요청에서 OpenAI는 이미지 입력과 웹 검색 도구를, Gemini는
  inline 이미지와 Google Search를 함께 포함하고, 직접 검색 요청일 때만 검색을
  강제하는지 검사한다.
- 화면 요청이라도 사용자가 검색을 명시적으로 금지하면 두 공급자 모두 웹 도구를
  생략하고 프롬프트도 화면 단독 분석으로 일치하는지 검사한다.
- 필수 검색에서 출처가 없으면 이미 흘려 보낸 답변을 다른 공급자에게 다시 묻지 않고
  `웹 출처를 확인하지 못한 답변` 표시와 함께 보여 주는지 검사한다. 스트리밍 도중
  오류가 나면 앞서 보인 글을 지우고 다음 공급자로 넘어가며, 모든 공급자가 오류를 내면
  검색 실패로 알린다.
- 검색 도구 실행·출처·화면·이전 외부 답변 중 하나라도 있으면 내용 변경 action은
  지워지지 않고 확인 대상으로 표시되며, 화면 이동 action은 바로 실행되는지 검사한다.
- 확인 대상 action은 변경 미리보기와 `적용`/`취소` 카드로 보이고, `적용`을 누를
  때만 실행되며 새 메시지·수정·새 대화에서 폐기되는지 검사한다.
- 검색 금지 문구는 검색 도구를 완전히 제거하고, 현재 글 조회는 로컬 요청으로
  분류하는지 검사한다.
- 검색·화면 답변의 외부 자료 메타데이터를 저장·복원하고, 다음 턴(`그럼 갤럭시는?`
  같은 후속 질문 포함)에도 이전 대화가 표시와 함께 프롬프트에 그대로 남는지 검사한다.
- 답변 대기 중에는 진행 단계와 경과 시간이 보이고, 보내기 버튼이 중단 버튼으로
  바뀌며, 중단하면 다른 공급자로 넘어가지 않고 입력이 입력칸에 되돌아오는지 검사한다.
- 화면 요청의 첫 공급자가 실패해도 같은 화면이 다른 공급자에게 재전송되지 않는지,
  네이티브 창 닫기·실패·취소 뒤 대기 이미지가 폐기되는지 검사한다.
- 고해상도 화면은 종횡비를 유지하고 8MB 예산 안으로 단계적으로 축소되는지 검사한다.
- 후속 탐색 제안은 답변 아래에서만 보이고 누르면 같은 대화의 새 질문으로 전송되는지,
  화면 포함 상태는 요청 성공·실패·새 대화 후 남지 않는지 확인한다.
- 답변은 스트리밍으로 받아 쓰는 대로 보이고, 답변 끝 `app-control` 제어 블록과 잘려
  들어온 블록 시작은 화면에 보이지 않는지 검사한다. 블록이 없거나 깨져도 답변은 남고
  알 수 없는 동작은 실행하지 않는다.
- 근거 문장에는 출처 링크와 번호가 붙고, 누르면 바로 열지 않고 `출처 확인` 창(문장·
  사이트·주소·검색어, `확인`/`취소`)을 거치는지 확인한다. `확인`에서만 브라우저를 연다.
- 답변마다 `앱 조작`·`웹 조사`·`글 상담`·`질문 답변` 이름표가 붙는지 확인한다.
- 검색 답변의 검색어·출처 기록이 다음 질문 요청에 `(검색 기록 · …)` 줄로 들어가는지 검사한다.
- 스트리밍 표시·제어 블록·분류·답변 서식과 문장 출처 위치는 `shared/rules/side-chat-cases.json`의
  공통 사례로 Windows와 Android가 같은 결과를 내는지 검사한다.
- 사이드 채팅 메시지·응답 대기·작업 연동·메시지 수정 화면의 QA 캡처와, 적용 확인
  카드·출처 없음 표시(`v5-01`)·진행 표시와 중단 버튼(`v5-02`)·출처 확인 창(`v5-03`)·
  답변 스트리밍(`v5-04`) 캡처가 존재한다.

## Android

- 본문과 후속 답변 입력창은 내용에 따라 최대 높이까지 커지고 이후 내부 스크롤된다.
- 키보드가 열린 상태에서도 현재 입력 줄과 주요 버튼에 접근할 수 있다.
- 버블 크기 설정이 즉시 반영되고 다음 실행에도 유지된다.
- 버블은 가장자리에 강제로 붙지 않고 사용자가 놓은 위치에 머문다.
- 길게 누르거나 드래그하면 하단 종료 영역이 나타난다.
- 종료 영역에 놓으면 서비스가 종료되고, 다른 곳에 놓으면 버블이 유지된다.
- X 버튼·뒤로가기·패널 바깥 터치가 모두 패널을 버블로 접는다.
- 화면 회전과 앱 전환 뒤에도 버블 위치가 유효하다.
- 포그라운드 서비스 알림에서 버블을 중지할 수 있다.
- 상황·추가 질문에는 인라인 편집 메뉴가 없고 추가 질문에는 음성 버튼도 없다.
- 원문의 편집 메뉴 버튼을 다시 누르면 접히며, 뒤로가기는 펼침 상태를 바꾸지 않는다.
- `다시 강화`·`반영하기`·결과 제안의 `예`는 누른 버튼 안에서 생성 상태를 표시하고
  처리 중 다른 생성 버튼을 비활성화한다.
- 결과 화면에서 재강화는 원문 보기 바로 왼쪽의 작은 아이콘, 이전·다음은
  `완성된 글 1/N` 줄 오른쪽의 아이콘 둘로 표시한다.
- AI 제안의 `예`와 직접 요구의 `반영하기`는 현재 결과를 기준으로 동작하고,
  직접 요구를 입력하면 제안 영역이 어두워지며 `예`는 비활성화된다.
- 재강화는 현재 결과·질문·추론을 요청 맥락에서 제외하고 원문과 기존 설정으로
  새 버전을 만든다.
- 사용자 문체·구조 지시는 기본 강화 규칙보다 우선하고 구체적인 줄·문장·문단·
  배수·글자 수 지시는 슬라이더 분량보다 우선한다. 어느 경우에도 입력에 없는
  사람·날짜·숫자·장소·사건 상태·원인·관계·부정을 추가하지 않는다.
- 최소 크기에서도 주요 버튼은 고정 노출되고 콘텐츠만 내부 스크롤하며, 큰 창에서는
  입력·결과 영역과 여백이 함께 확장된다.
- 콘텐츠를 스크롤하거나 창 크기를 바꿔도 상단 로고·메뉴의 화면 위치가 유지된다.
- 첫 완성 질문은 글 유형·주제·목적을 예상해 추가 다듬기 허용을 묻고, 후속 입력
  안내가 `아니면 다른 요구 사항 입력`인지 확인한다.
- 사이드 채팅은 같은 오버레이의 독립 화면으로 열리고 현재 원문·상황·결과·
  후속 요구·강화 범위와 버전을 요청마다 인식한다.
- 모든 글 강화기 화면의 최상단에서 `기록` 바로 오른쪽에 `β`가 표시되고,
  접힌 도구 메뉴에는 파일·화면·말하기만 남는지 확인한다.
- 채팅 메시지 수정 시 그 지점 이후 대화가 제거되고 수정문부터 다시 답하며,
  새 대화 직후 입력칸이 활성 상태인지 확인한다.
- 최상단 `새 채팅 → 글로` 순서, 사용자 메시지 왼쪽의 `수정`, AI 답변 오른쪽의
  `복사` 배치를 확인한다.
- 채팅 기능 명령은 글 강화기 화면·값·실행에 연결하되 파일·화면·음성·기억
  승인을 자동 실행하지 않는다.
- 채팅 재강화는 현재 결과 없이 원문으로 새 버전을 만들고, 결과 반영도 기존
  버전을 덮어쓰지 않는지 확인한다.
- 사이드 채팅에서 X로 접은 뒤 버블을 누르면 채팅이, 글 강화기에서 X로 접은 뒤
  버블을 누르면 글 강화기가 복원되는지 확인한다.
- 채팅을 처음 열거나 초기화한 직후 키보드를 강제로 표시하지 않는다.
- 사이드 채팅의 `현재 화면`은 시스템 화면 공유 동의를 거쳐 한 장만 캡처하고 채팅으로
  복귀한다. 취소·실패 때에도 오버레이와 입력 상태가 정상 복구되는지 확인한다.
- 채팅용 캡처 파일은 글 첨부 목록·채팅 기록에 들어가지 않으며 검색 요청 완료 후
  삭제되는지 검사한다. 화면 포함 중임을 작은 상태 버튼으로 취소할 수 있어야 한다.
- 검색 답변의 후속 탐색 질문은 최대 3개만 표시하고, 탭하면 기존 대화 맥락을 유지해
  즉시 다음 검색으로 이어지는지 확인한다.
- `⌕ 검색` 버튼은 다음 질문 한 번만 검색을 강제하고, 답변 대기 중에는 `중단` 버튼과
  진행 단계·경과 시간이 보이며, 외부 자료가 섞인 대화의 변경 제안은 적용 확인
  카드를 거치는지 확인한다.
