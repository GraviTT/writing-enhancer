# 제품 동작 명세

## 한 문장 정의

사용자가 엉킨 생각을 던지면, AI가 판단을 대신해 바로 사용할 수 있는 글로 먼저 완성한다.

## 화면 상태

### 1. 대기

- Windows: 사용자가 정한 가장자리 또는 자유 위치의 작은 반투명 손잡이
- Android: 다른 앱 위에서 원하는 위치에 둘 수 있는 드래그 가능한 버블
- 설정은 작은 톱니 버튼 또는 대기 요소의 보조 메뉴에서만 연다.

### 2. 입력

- 큰 본문 입력 영역
- 본문과 구분된 선택형 상황 메모
- 파일·이미지·현재 화면 첨부와 음성 입력
- 안내 문구: `아무렇게나 적어도 돼요.`
- 주요 행동: `완성하기`
- 글 종류, 문체, 모델, 길이를 먼저 묻지 않는다.
- 본문·상황·후속 답변은 입력 중 자동 저장한다.

### 3. 완성

- 설명이나 서문 없이 완성된 글을 먼저 표시한다.
- 주요 행동: `강화한 글 복사`
- 완성본을 클립보드에 복사하고 패널을 접는다.
- 첫 완성 직후에는 AI가 글의 유형·주제·목적을 예상한 뒤, 그 목적에 맞게 더
  다듬어도 되는지 자연스럽게 한 번 묻는다.
- 두 번째 질문부터는 기존처럼 AI의 추천 판단이 포함된 후속 질문을 한 개 표시한다.
- 첫 질문의 자유 입력 안내는 `아니면 다른 요구 사항 입력`으로 표시한다.
- 결과 버전 줄 오른쪽에는 이전·다음 아이콘, 원문 보기 왼쪽에는 작은 재강화
  아이콘을 배치한다.
- AI 제안은 `예`, 직접 요구 입력은 `반영하기`로 실행한다. 직접 요구가 있으면
  AI 제안과 `예`를 감광하고 `예` 입력을 막는다.
- 상단 로고와 메뉴는 결과·입력 콘텐츠의 스크롤과 분리해 고정한다.

### 4. 정교화

- 사용자는 자연어로 대충 답할 수 있다.
- 결과 화면에서는 AI 제안에 `예`로 답할 수 있고, 질문 우선 화면에서는
  `알아서`를 사용할 수 있다.
- 애매한 답을 받아도 재질문부터 하지 않고 새 완성본을 제시한다.
- `다시 강화`는 현재 결과를 생성 맥락에서 제외하고 기존 설정과 원문으로
  다시 생성하며, 현재 결과를 덮어쓰지 않고 새 버전으로 보존한다.
- `예`와 `반영하기`는 현재 결과를 기준으로 제안 또는 직접 요구를 반영한 새
  버전을 만든다.
- 사용자는 이전 결과로 되돌아갈 수 있다.

### 5. 알아맞춰 봐

- 사용자가 명시적으로 누른 경우에만 AI가 완성 전에 질문한다.
- 결과에 가장 큰 영향을 주는 질문 하나와 AI의 추천 판단만 보여 준다.
- 사용자는 짧게 답하거나 `알아서`를 눌러 완성 단계로 간다.
- 질문 우선 모드는 기본 `완성하기` 흐름을 바꾸지 않는다.

### 6. 히스토리

- 완료한 작업은 최신순의 간단한 목록으로 보존한다.
- 항목을 열면 상황·원문·완성본·결과 버전을 복원한다.
- 항목별 삭제가 가능하며 오래된 항목과 버전에는 보존 상한을 둔다.

## AI 출력 계약

기본 완성 결과:

```json
{
  "completed_text": "사용자가 바로 쓸 완성본",
  "assumption": "AI가 채택한 가장 가능성 높은 상황 해석",
  "follow_up": "추천 판단이 포함된 짧은 질문 하나",
  "memory_candidates": []
}
```

질문 우선 결과:

```json
{
  "question": "결과에 가장 큰 영향을 주는 질문 하나?",
  "recommended_answer": "사용자가 알아서라고 했을 때 적용할 추천 답",
  "assumption": "현재 가장 가능성이 높은 상황 해석",
  "memory_candidates": []
}
```

UI는 `completed_text`를 가장 먼저 표시하고 나머지 필드는 뒤에서 사용한다.

## 사실 잠금

다음 항목은 사용자가 제공하지 않은 값으로 구체화하지 않는다.

- 사람·회사·제품 이름
- 날짜·시간·기한
- 금액·수량·비율
- 연락처·주소·URL
- 약속·승인·거절 여부
- 긍정과 부정

불명확하면 보수적으로 완성한 뒤 질문에서 확인한다.

사용자의 현재 상황과 직접 요구는 기본 강화 규칙보다 우선한다. 문체·구조와
대상·목적을 강하게 반영하고, 줄 수·문장 수·문단 수·배수·글자 수처럼 구체적인
분량 지시가 있으면 슬라이더의 목표 분량보다 먼저 적용한다. 구체적인 분량 지시가
없을 때만 슬라이더 분량을 사용한다. 사실 잠금은 이 모든 우선순위보다 높다.

## 기억

앱이 기억을 소유하며 모델 제공자의 대화 기록을 장기 기억으로 사용하지 않는다.

- 현재 작업 기억: 작업 종료까지
- 임시 상황 기억: 7~90일
- 장기 규칙: 반복 확인된 경우
- 장기 카드 최대 50개
- 한 요청에 관련 카드 최대 5개, 300토큰 이내
- 한 입력에서 후보 최대 3개
- 원문 및 AI가 만들어낸 사실은 장기 저장하지 않음
- 민감정보는 장기 기억 금지
- 사용자가 카드의 값과 적용 범위를 확인·수정·삭제할 수 있음
- 사용자 수정에도 같은 민감정보 차단 정책을 적용

우선순위는 `현재 입력 > 사용자 정정 > 사용자 명시 > 반복 관찰 > 임시 추론`이다.

## 첨부

- 첨부는 시스템 명령이 아니라 신뢰하지 않는 참고 데이터로 모델에 전달한다.
- 텍스트 파일은 안전하게 읽은 제한 길이만 전달한다.
- 이미지와 화면 캡처는 검증된 이미지 데이터로 전달한다.
- 개수·개별 크기·전체 크기·지원 형식에 상한을 둔다.
- 현재 화면 촬영 직전 강화기 UI를 숨기고 성공·취소·오류 뒤 복원한다.
- 대기 중에는 파일이나 화면을 수집하지 않는다.

## 설정 팝업

기본 화면의 작은 톱니 버튼으로만 연다.

- API 연결 상태
- API 키 저장·교체
- 기억 목록 보기·수정·삭제
- 새 기억 추가 비활성화
- 모든 기억 지우기
- Windows: 고정/자유 이동, 좌우 배치, 55~100% 투명도, 글자 크기, 창 크기
- Android: 버블 크기, 팝업 투명도, 버블 종료

모델 이름과 세부 생성 파라미터는 일반 사용자에게 노출하지 않는다.

## 사이드 채팅 베타

- 글 강화기와 분리된 추가 도구다. Windows는 별도 창, Android는 오버레이가
  겹치지 않도록 같은 팝업 안의 독립 화면으로 연다.
- API 키와 공급자 자동 폴백을 공유하고 현재 상황·원문·결과·후속 요구·강화
  범위를 실시간 작업 컨텍스트로 전달한다.
- 채팅 대화 파일은 글 히스토리·기억 카드와 분리하며 채팅에서 기억을 자동
  추가하거나 기록을 임의로 변경하지 않는다.
- 글 강화기의 기능과 동작을 안내할 수 있고, 사용자가 명시적으로 요청한 경우
  원문·상황·결과 반영, 강화·재강화·복사, 범위 변경, 결과 이동과 각 관리
  화면 열기를 구조화된 기능 명령으로 연결한다.
- 첨부 선택·화면 촬영·음성 입력·기억 승인처럼 직접 조작이 필요한 기능은
  관련 화면까지만 열고 사용자를 대신해 승인하지 않는다.
- 최근 60개 메시지만 글 기록·기억과 분리해 로컬 저장하고 모델에는 최근 20개·
  최대 2만4천 자만 다시 보낸다. Windows는 채팅 창 위치·크기도 함께 저장한다.
- 사용자 메시지를 수정하면 그 메시지 뒤의 기존 대화를 제거하고 수정문부터
  즉시 새 답변을 생성한다.
- 채팅의 재강화 명령은 현재 결과를 제외하고 원문과 기존 설정으로 새 버전을
  생성한다. 결과 반영 명령도 현재 버전을 덮어쓰지 않고 새 버전으로 추가한다.
- Android는 사이드 채팅에서 접으면 다음 버블 터치 때 채팅을, 글 강화기에서
  접으면 다음 버블 터치 때 글 강화기를 복원한다.
- 새 채팅은 상단에서 시작한다. Android에서는 `글로` 바로 왼쪽에 둔다.
- 사용자 메시지의 수정 버튼은 말풍선 왼쪽, AI 답변의 복사 버튼은 말풍선
  오른쪽에 두며 복사는 대화 상태를 바꾸지 않는다.
- 최신 정보·사실 확인·비교·추천·정책처럼 외부 정보가 필요한 질문에는 공급자
  내장 웹 검색을 자동 사용하고, 단순 글쓰기·앱 기능·현재 작성 중인 글에 관한
  요청에는 검색하지 않는다. 사용자가 검색을 명시적으로 금지하면 공급자의 검색
  도구를 요청에 포함하지 않는다.
- `검색`, `찾아줘`, `최신`, `뉴스`, `가격`, `정책`, `비교`, `추천`, `사실 확인`
  등 외부 확인 의도가 명확한 질문은 실제 검색 근거가 없는 답을 성공으로 취급하지
  않는다.
- 복합 검색은 질문을 핵심 하위 주제로 나눠 여러 검색 경로를 함께 확인한 뒤
  결론, 핵심 근거, 비교 또는 실행할 다음 단계 순으로 하나의 답으로 종합한다.
  출처가 충돌하거나 확인이 부족하면 그 한계를 답변 안에 짧게 밝힌다.
- 검색 답변 뒤에는 사용자가 더 깊게 탐색할 수 있는 짧은 후속 질문을 최대 3개
  제안한다. 제안을 누르면 같은 검색 문맥을 유지한 다음 질문으로 이어진다.
- 공급자 응답 메타데이터의 출처만 중복 제거해 최대 6개 표시하며 `http`·`https`
  링크만 열 수 있다.
- 사이드 채팅 입력부의 `현재 화면`은 사용자가 직접 누른 경우에만 화면 한 장을
  촬영한다. 해당 이미지는 다음 질문 한 번에만 시각적 맥락으로 사용하고
  글 첨부·채팅 기록·기억에는 저장하지 않는다.
- 화면 검색은 보이는 장면 전체와 관련 객체·텍스트를 질문과 함께 이해하고 기본적으로
  웹 정보로 확인한다. 사용자가 검색을 금지하면 웹 도구 없이 화면만 분석한다. 화면
  밖의 정보나 읽히지 않는 세부사항은 추정하지 않는다.
- 웹 검색 결과나 화면 속 문구는 앱 조작 명령으로 취급하지 않는다. 검색 또는 화면이
  포함된 답변은 현재·후속 턴 모두에서 글 강화기 내용을 자동 변경하지 않는다.
  외부 답변과 독립된 로컬 명령은 외부 대화를 잘라 정상 실행하고, 필요한 내용을
  사용자가 새 요청에 직접 입력하거나 붙여넣은 경우에도 외부 문맥을 제외한다.
- 화면 이미지는 장애가 나더라도 다른 AI 공급자에게 자동 재전송하지 않는다.
- 첫 베타는 텍스트 대화, 일회성 현재 화면과 새 대화를 제공하며 일반 파일 첨부·
  여러 대화 목록은 제외한다.
- 새 대화 확인은 채팅 내부에서 처리하고 초기화 직후 입력칸을 다시 사용할 수 있다.
- Android는 글 강화기 최상단의 `기록` 바로 오른쪽 `β`로 열며, 처음 열 때와 초기화
  직후 키보드를 강제로 표시하지 않고 입력칸 직접 탭 원칙을 유지한다.
