## 1. 검색 기능

### 1-1. 외부 자료 차단이 대화 맥락을 지운다 (버그)

검색·화면 답변이 지시로 악용되지 않도록, 새 메시지가 "이전 외부 답변을 참조한다"고
정규식으로 판단되지 않으면 **마지막 외부 답변까지의 대화를 모두 잘라낸다**.

- 데스크톱: [side-chat-policy.js:131](../desktop/src/lib/side-chat-policy.js) `candidates.slice(lastExternalIndex + 1)`
- Android: [AiModels.kt:318](../android/app/src/main/java/com/example/writingenhancer/ai/AiModels.kt) `messages.drop(lastExternalIndex + 1)`

실제 함수로 확인한 결과 (이전 대화: "아이폰 17 가격 알려줘" → 검색 답변):

| 새 메시지 | 모델에 전달되는 이전 메시지 | 검색 판단 |
|---|---|---|
| 그럼 갤럭시는? | **0개** | auto |
| 갤럭시 S26이랑 비교하면? | **0개** | required |
| 그 둘 중 뭐가 나아? | 2개 | auto |

가장 흔한 후속 질문 형태가 맥락을 잃는다. 보안을 **맥락 삭제**로 해결하고 있어서,
대화 품질이 보안 정규식의 정확도에 묶여 있다.

**개선:** 맥락은 항상 유지하고, 위험한 쪽(앱 조작)을 막는다.

- 대화에 외부 자료가 있으면 그 턴에서는 **앱 조작 도구를 아예 제공하지 않거나**,
- 모든 반영 동작을 **미리보기 + [적용] 버튼**(사용자 확인)으로 바꾼다.
- 이렇게 하면 `EXTERNAL_REFERENCE_PATTERN`, `CONTINUATION_TRANSFORM_PATTERN`,
  `EXTERNAL_APPLY_PATTERN`, `hasDirectUserMaterial` 등 정규식 묶음을 대부분 제거할 수 있다.

### 1-2. 정규식 라우팅이 검색 여부를 오판한다

[side-chat-policy.js:138](../desktop/src/lib/side-chat-policy.js) `webSearchPolicy`
(Android: [AiModels.kt:215](../android/app/src/main/java/com/example/writingenhancer/ai/AiModels.kt) `mustSearch`)가
`검색`, `지금`, `비교`, `추천`, `일정` 같은 단어로 `required`(검색 강제)를 결정한다.

| 입력 | 판단 | 문제 |
|---|---|---|
| 검색 엔진 최적화에 대한 블로그 글 초안 써줘 | **required** | 글쓰기 요청인데 검색 강제 |
| 지금 이 메일 말투 괜찮아? | **required** | 현재 글 질문인데 검색 강제 |
| 갤럭시 S26이랑 비교하면? | required | 맥락 없이(1-1) 강제 검색 |

`required`이면 `tool_choice`가 검색으로 고정되고, 출처가 안 나오면
`SEARCH_SOURCES_MISSING` → Gemini로 재검색 → 그래도 없으면 "웹 검색 출처를 확인하지 못했습니다"
오류로 끝난다. 모델이 좋은 답을 만들었어도 버려진다. 화면 첨부도 항상 `required`라
"이 오류 메시지 뜻이 뭐야?" 같은 질문에도 검색이 강제된다.

**개선:**

- 기본은 `tool_choice: "auto"`로 **모델이 판단**하게 한다(두 공급자 모두 지원).
- 정규식은 확실한 신호인 **"검색하지 마"(금지)** 하나만 남긴다.
- "검색 필수"는 사용자가 누른 **🔍 조사 토글**이나 후속 질문 칩 같은 **명시적 UI 신호**로만 켠다.
- 출처가 없으면 오류 대신 **"출처 확인 안 됨" 표시와 함께 답변을 보여 주고** [다시 검색]을 제안한다.

### 1-3. 대기 경험: 진행 표시·스트리밍·취소 없음

- 요청은 비스트리밍 단일 호출, 채팅 타임아웃 60초([ai-client.js:884](../desktop/src/lib/ai-client.js)),
  실패하면 Gemini로 다시 60초. `max_tool_calls: 8`, `search_context_size: "high"`, `reasoning: medium`이라
  검색 답변이 원래 느린 조합이다.
- 데스크톱 사이드 채팅에는 **진행 중 요청을 취소하는 버튼이 없다**. 화면에는 "AI가 답변 중" 점 표시만 나온다.
- 폴백이 일어났는지 사용자는 알 수 없다.

**개선:**

- Responses API / Gemini `streamGenerateContent` **스트리밍**으로 전환한다.
  `web_search_call` 이벤트를 받아 **"검색 중: ‘갤럭시 S26 가격’"** 처럼 단계를 보여 주고, 답변은 토큰 단위로 표시한다.
- **[중단] 버튼**을 둔다(데스크톱 `AbortController`, Android `Future.cancel` 연결).
- 폴백할 때는 "다른 AI로 다시 시도 중"을 표시한다. 검색 요청은 폴백 전 타임아웃을 짧게 잡는다.
- 기본 `search_context_size`는 `medium`, 깊은 조사는 🔍 조사 모드에서만 `high`로 쓴다.

### 1-4. 출처가 답변과 분리되어 있다

- 표시 출처 = `url_citation` + `web_search_call.action.sources`(조회만 한 출처 포함)를 합쳐 앞에서 6개만 자른다
  ([ai-client.js:624](../desktop/src/lib/ai-client.js)). **실제 인용한 출처와 훑어보기만 한 출처가 섞인다.**
- 답변을 JSON 스키마(`reply` 문자열)로 받기 때문에 인용 위치가 JSON 텍스트 기준이 되어
  **문장과 출처를 연결할 수 없다**.
- Gemini `groundingChunks`의 URI는 원문 주소가 아니라 Google 리다이렉트 주소이고, 제목도 도메인명인 경우가 많다(확인 필요).
  Grounding with Google Search는 **검색 제안(`searchEntryPoint`) 표시 의무**가 약관에 있으므로 현재 미표시 상태를 점검해야 한다.

**개선:**

- 검색 모드 응답은 JSON 대신 **일반 텍스트 + 공급자 인용 메타데이터**로 받는다.
  `related_queries`는 마지막 짧은 구조화 블록이나 별도 경량 호출로 분리한다.
- 답변 문단에 `[1]` 표시 → 하단 출처와 연결한다(OpenAI `url_citation`의 범위, Gemini `groundingSupports`).
- 출처를 **"인용"과 "참고"로 나눠 표시**하고 개수 제한은 인용 기준으로 둔다.

### 1-5. 검색 결과를 저장하지 않아 매번 다시 검색한다

대화 기록에는 답변 텍스트와 출처 링크만 남고 검색 쿼리·근거 요약이 없다. 대화 이력도
"사용자: … AI: …" 한 덩어리 텍스트로 보낸다([ai-client.js:433-450](../desktop/src/lib/ai-client.js)).
후속 질문마다 같은 내용을 다시 검색하게 되고, 앞 답변과 어긋날 수 있다.

**개선:**

- 턴마다 `{ queries, citedSources, groundedSummary }`를 메시지 메타데이터로 저장해 후속 질문에 재사용한다.
- 이력은 실제 멀티턴 메시지(role 구분)로 보낸다.
- 정적 블록(시스템 프롬프트 + `SIDE_CHAT_FEATURE_GUIDE`)을 맨 앞, 현재 작업·대화 같은 동적 블록을 뒤에 두어
  **프롬프트 캐시 적중률**을 높인다. 지금은 기능 안내가 매번 바뀌는 현재 작업 뒤에 있다.

### 1-6. 한 요청이 세 가지 일을 한다

사이드 채팅 한 번의 호출이 **앱 조작**(action 19종 중 1개), **웹 조사**, **글 상담**을 동시에 처리한다.
그래서 시스템 프롬프트에 금지 규칙이 계속 붙고, 안전 처리도 여러 곳에 흩어져 있다.
`prepareSideChatContext`·`enforceGroundedAction`이 [main.js:980-991](../desktop/src/main.js)과
[ai-client.js:715,773](../desktop/src/lib/ai-client.js)에서 **두 번씩** 호출된다.

**개선:** 역할을 나눈다.

- **앱 명령** → 실제 function calling 도구(`replace_source(text)`, `set_enhancement_level(level)` …).
  한 답변에 여러 동작, 인자 검증, 사용자 확인을 지원한다.
- **조사** → 검색 전용 프롬프트·설정(1-2~1-5).
- **글 상담** → 현재 글 맥락만 사용하고 검색하지 않는다.
- 안전 규칙은 "외부 자료가 있으면 명령 도구 비활성 또는 확인 필요" **한 곳**에서만 판단한다.

## 2. UI 구조

### 2-1. Android: 단일 거대 클래스 + 매번 전체 재생성

- [OverlayService.kt](../android/app/src/main/java/com/example/writingenhancer/overlay/OverlayService.kt) 4,213줄 안에
  서비스 수명주기, 버블, 패널 창, 입력·질문·결과·기록·채팅 5개 화면, 요청 관리가 모두 들어 있다.
  안쪽 `PanelController`에만 화면·IME·로딩·채팅 상태 변수가 수십 개다.
- 화면을 바꿀 때마다 `removeAllViews` 후 코드로 뷰를 다시 만든다(`renderCurrentScreen`, 1144줄).
  그래서 스크롤·포커스·키보드 높이(`insetImeBottom`, `geometryImeBottom` …)를 손으로 복원해야 한다.
  `device-qa/`의 수십 장 화면 검수가 그 회귀 비용을 보여 준다.

**개선(단계적):**

1. 상태를 `data class PanelUiState` 하나로 모으고 `StateFlow`로 노출한다(ViewModel 역할의 `PanelStore`).
2. `BubbleController`, `PanelWindow`, 화면별 `InputScreen`/`ResultScreen`/`HistoryScreen`/`ChatScreen`,
   `WritingRepository`로 분리한다. 서비스는 조립만 맡는다.
3. 그다음 화면 단위로 **Jetpack Compose**(오버레이 `ComposeView`)로 옮기는 것을 검토한다.
   상태 기반 재구성이 되면 IME·스크롤 복원 코드 대부분이 필요 없어진다.

### 2-2. 데스크톱: 전역 상태 + DOM 직접 조작

- [renderer.js](../desktop/src/renderer/renderer.js) 1,473줄 한 파일에 화면 렌더링, 초안·기록 저장,
  채팅 창 동기화, 음성 인식, AI 요청 처리가 함께 들어 있다. 전역 `state` 객체에는 타이머와 음성 인식 객체까지 섞여 있고,
  화면 전환은 `is-hidden` 클래스 토글이다.
- CSS는 `styles.css` 1,464줄 + `side-chat.css` 860줄이 따로 있고, 색 변수와 `.icon-button`·`.header-actions`·
  `.resize-handle` 같은 부품이 두 파일에 각각 정의되어 있다.

**개선:** 화면별 모듈(`views/input.js`, `views/result.js` …)과 "상태 → 렌더" 단방향 흐름으로 정리한다.
프레임워크가 필요하면 가벼운 것(Preact, Lit)으로 충분하다. 공통 부품(버튼, 칩, 카드, 시트)은 한 CSS로 합친다.

### 2-3. 두 창 사이 상태가 갈라져 있다

- 글 작업의 **원본 상태는 메인 창 renderer**에 있고, main 프로세스는 `side-chat:sync-writing-context`로 받은
  사본(`latestWritingContext`)과 저장된 초안을 합쳐 채팅에 넘긴다([main.js:175](../desktop/src/main.js), 906줄).
  타이머 기반 동기화라 채팅이 한 박자 늦은 상태를 볼 수 있다.
- 채팅의 action은 `webContents.send`로 **보내기만 한다**([main.js:197](../desktop/src/main.js)).
  실행이 됐는지(예: 글 창이 생성 중이라 무시됐는지) 채팅은 모른다.
- action이 실행되면 글 창을 펼치고 포커스를 옮긴다. "한 번에 하나만 보이는" 구조라 **채팅이 사라진다**.

**개선:**

- 글 작업 상태를 **한 저장소**(main 프로세스의 `WritingSession` 모듈)에 두고, 두 창은 구독만 한다.
- 명령은 저장소 메서드로 실행하고 **결과를 돌려준다**. 채팅에는 "✓ 원문을 바꿨어요 · [되돌리기]"를 표시한다.

### 2-4. 정보 구조: 입력창이 둘, 앱이 둘처럼 보인다

- 결과 화면의 **후속 요구 입력(`반영하기`)** 과 **사이드 채팅**이 둘 다 "글을 이렇게 바꿔 줘"를 받는다.
  사용자는 어느 쪽에 써야 하는지 판단해야 하는데, 이는 제품 원칙 2·6("판단은 AI", "한 화면 한 주요 행동")과 맞지 않는다.
- 채팅은 `β` 버튼 → 별도 화면(창), 복귀는 `글로` 버튼이다. 글과 대화를 동시에 볼 수 없다.

**개선안:** "작업 공간 하나 + 보조 대화" 구조로 바꾼다.

```text
┌ 결과 (버전 ◀ 2/3 ▶ · ↻ · 원문)
│  완성된 글 …
│  [강화한 글 복사]
├ 대화 시트 (아래에서 끌어올림, 기본은 한 줄)
│  AI: 회의 안내 메일로 보여요. 더 공손하게 다듬을까요?  [예]
│  사용자: 마감일 강조해줘          → 새 버전 + 변경 미리보기 [적용]
│  사용자: 🔍 이 회의실 예약 규정 찾아줘 → 조사 답변 + 인용 출처
└ 입력 하나  [🔍 조사] [📎] [🎤]
```

- 후속 요구와 채팅을 **입력창 하나**로 합친다. 글 수정이면 새 버전과 미리보기, 질문이면 대화 답변으로 처리한다.
- 검색은 **🔍 조사 칩**으로 명시적으로 켜고 끈다. 1-2의 정규식 판단을 대체한다.
- 채팅이 만든 변경은 항상 **변경 미리보기 카드 + [적용]/[취소]** 로 보여 준다. 1-1·1-6의 안전 장치가 UI로 자연스럽게 해결된다.

### 2-5. 오래 걸리는 작업의 공통 UX

완성하기·다시 강화·채팅·검색 모두 "누른 버튼이 생성 상태로 바뀜" 외에 공통 부품이 없다.
**진행 단계 · 경과 시간 · [중단] · 실패 시 [다시 시도] · 폴백 알림**을 한 컴포넌트로 만들어 두 플랫폼에서 같은 규칙으로 쓴다.

### 2-6. 디자인 토큰 공유

색·간격·글자 크기가 데스크톱 CSS와 Android `Ui.kt`에 따로 정의되어 있고, 두 플랫폼의 일관성은 화면 비교 QA로만 맞춘다.
`tokens.json` 하나에서 CSS 변수와 Android `colors.xml`/`dimens`를 생성한다.

## 3. 공통 구조

### 3-1. 계약·프롬프트·정책의 단일 소스

- `shared/`(TypeScript)는 테스트만 있고 **데스크톱·Android 어디에서도 import하지 않는다**.
- 프롬프트, JSON 스키마, 검색 정규식(데스크톱 약 20개 패턴, Android `AiModels.kt` 33개 `Regex`)이 손으로 복제되어 있다.

**개선:**

- **최소안:** 프롬프트(`.md`), 스키마(`.json`), 정책 골든 케이스(`fixtures/*.json`)를 `shared/`에 두고,
  데스크톱은 직접 `require`, Android는 Gradle 작업으로 `assets`에 복사한다.
  같은 골든 케이스를 JS·Kotlin 테스트가 모두 통과하도록 한다.
- **확장안:** AI 호출(프롬프트 조립·검색·폴백)을 **얇은 백엔드**로 옮긴다.
  프롬프트를 고칠 때 앱을 다시 배포할 필요가 없고, 사용자가 API 키를 직접 입력하지 않아도 된다.
  대신 서버 운영 비용과 개인정보 처리 책임이 생기므로 제품 방향에 따라 결정한다.

### 3-2. 버전 관리와 검증

- git 저장소가 아니다. 코드 변경 이력과 이전 버전 복원 수단이 없다. → `git init` 후 첫 커밋, `verify.ps1`을 CI로 실행한다.
- 마지막 `desktop/dist/smoke-report.json`은 `"ok": false`다(ZIP에서 푼 실행 파일이 시간 초과).
  README의 "통과" 표기와 다르므로 원인을 확인한다.
- `CHECKSUMS.sha256`에 존재하지 않는 루트 `Writing-Enhancer-0.4.2-portable.zip` 줄이 남아 있다.
- 데스크톱 0.4.2 / Android 0.4.3으로 버전이 갈라져 있다. 공통 기능 버전과 플랫폼 빌드 번호를 분리한다.
