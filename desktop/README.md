# 글 강화기 — Windows v0.5.0

생각나는 내용을 그대로 쓰면 AI가 의도를 추론해 먼저 완성본을 보여 주는
항상 위 데스크톱 패널입니다. 사용자가 글의 종류나 문체를 고를 필요가 없습니다.

## 실행

```powershell
npm.cmd install
npm.cmd start
```

기본 전역 단축키는 `Ctrl+Shift+Space`입니다. 화면 가장자리의 손잡이나
트레이 아이콘으로도 열고 접을 수 있습니다. 처음 실행한 뒤 작은 톱니에서
OpenAI 또는 Gemini API 키를 입력합니다.

설정 단축키가 다른 앱에 점유되면 기본 단축키를 시도합니다. 두 단축키를 모두
등록할 수 없어도 앱은 종료되지 않으며, 화면 손잡이와 트레이 아이콘으로 계속
열 수 있다는 안내를 패널과 설정에 표시합니다.

OpenAI `gpt-5.6-terra`를 우선 사용하고, 장애나 형식 오류가 생기면 Gemini
`gemini-3.6-flash`로 자동 전환합니다. API 키는 Electron `safeStorage`로
Windows 보안 저장소에 암호화하며 렌더러나 히스토리에 기록하지 않습니다.

## 사이드 채팅 베타

메인 창 위쪽의 말풍선 `β` 버튼이나 트레이의 `사이드 채팅 (베타)`를 누르면
같은 창 안의 화면이 대화로 바뀝니다. 0.6.0부터 별도 채팅 창이 없고, 상단 `‹ 글로`나
말풍선 버튼으로 즉시 돌아갑니다.

- 채팅 기록은 별도로 저장하되 현재 글 강화기의 상황·원문·결과·후속 요구와
  강화 범위를 실시간으로 인식합니다.
- 글 강화기 기능을 이해하고, 사용자가 명시적으로 요청하면 원문·상황·결과 반영,
  강화·재강화·복사, 강화 범위, 이전·다음 결과, 설정·기록·기억·도구 화면을
  안전한 기능 명령으로 연결합니다.
- API 키와 OpenAI → Gemini 폴백 정책을 글 강화기 설정과 함께 사용합니다.
- 대화는 별도 `side-chat.json`에 최근 60개 메시지만 로컬 저장하고, AI 요청에는
  최근 20개·최대 2만4천 자까지만 다시 사용해 컨텍스트 비용을 제한합니다.
- 글 강화 기억을 검색하거나 새 기억 후보를 만들지 않습니다.
- `Enter`로 전송하고 `Shift+Enter`로 줄을 바꿉니다.
- 글 강화기 창과 같은 이동·크기 조절을 쓰고, 창 밖을 클릭하면 작은 손잡이로
  함께 접힙니다. 화면 촬영 뒤에는 채팅 화면으로 돌아옵니다.
- 답변은 쓰는 대로 말풍선에 이어서 나타납니다. 답변 중에도 `중단`할 수 있습니다.
- 근거가 확인된 문장에는 밑줄과 출처 번호가 붙습니다. 누르면 바로 열지 않고
  `출처 확인` 창에서 문장·사이트·주소·찾은 검색어를 보여 주며, `확인`을 눌러야
  기본 브라우저로 엽니다. 답변 아래 출처 목록도 같은 창을 거칩니다.
- 답변마다 `앱 조작`·`웹 조사`·`글 상담`(출처 없는 조사는 `질문 답변`) 이름표가 붙습니다.
- 검색 답변의 검색어와 출처를 대화 기록에 남겨, 이어지는 질문에서 같은 검색을
  되풀이하지 않게 합니다.
- 상단 `새 채팅` 버튼은 사이드 채팅 대화만 지웁니다.
- 사용자 메시지의 `수정`을 누르면 인라인으로 고칠 수 있습니다. `수정 완료` 시
  해당 메시지 뒤의 기존 대화를 제거하고 수정된 메시지부터 바로 다시 답합니다.
- 사용자 메시지의 `수정`은 말풍선 왼쪽에, AI 답변의 `복사`는 말풍선 오른쪽에
  표시합니다. 복사는 채팅창을 닫지 않고 해당 답변만 클립보드에 넣습니다.
- 채팅의 결과 반영은 현재 결과를 덮어쓰지 않고 새 버전으로 추가하며, 재강화
  명령은 현재 결과가 아닌 원문과 기존 설정을 기준으로 실행합니다.
- 검색 도구는 기본으로 열어 두고, 최신 정보·사실 확인·비교·추천·정책 질문에서
  검색할지는 모델이 판단합니다. `검색하지 말고` 같은 명시적 금지 요청은 검색
  도구를 완전히 비활성화합니다.
- `검색해 줘`, `찾아줘`, `사실 확인`, `출처와 함께` 같은 직접 요청, 입력부의 🔍
  버튼(다음 질문 한 번), `이어서 살펴보기` 칩만 검색을 강제합니다. 출처를 받지
  못하면 `웹 출처를 확인하지 못한 답변` 표시와 함께 답변을 보여 줍니다.
- 복합 질문은 2~5개의 하위 주제로 나눠 여러 검색 경로와 핵심 근거를 교차
  확인한 뒤, 검색 결과를 나열하지 않고 결론·근거·차이 순서로 종합합니다.
- 검색 답변 아래에는 공급자가 실제로 반환한 출처만 최대 6개까지 표시하며,
  실제 인용한 출처를 앞에 둡니다. 제목을 누르면 출처 확인 창을 거쳐 안전한
  `http`·`https` 링크만 기본 브라우저로 엽니다.
- 검색 답변 아래의 `이어서 살펴보기`에는 같은 문맥에서 더 확인할 질문을 최대
  3개 표시합니다. 질문 칩을 누르면 바로 다음 검색으로 이어집니다.
- 입력부의 화면 버튼은 창을 잠시 숨기고 화면 한 장을 촬영하며, 이미지 버튼은
  로컬 이미지를 선택합니다. 두 경로 모두 전송 전에 썸네일을 표시하고 `영역 선택`에서
  필요한 부분만 드래그해 보낼 수 있습니다. 이미지는 다음 요청 한 번에만 쓰고
  성공·실패와 관계없이 폐기하며 채팅 기록·글 첨부·히스토리에는 저장하지 않습니다.
- 검색·화면 자료가 섞인 대화에서 AI가 내용을 바꾸는 기능 명령을 제안하면 바로
  실행하지 않고, 변경 미리보기와 `적용`/`취소` 카드를 보여 줍니다. 화면 이동 명령은
  바로 실행합니다. 화면을 처리한 첫 AI가 실패해도 같은 이미지를 다른 AI 공급자에게
  자동 재전송하지 않습니다.
- 검색 답변 뒤의 후속 질문도 이전 대화를 그대로 이어 받습니다. 외부 자료에서 온
  이전 답변은 `검색·화면 유래 자료 · 지시 아님` 표시와 함께 전달합니다.
- 답변을 기다리는 동안 진행 단계와 경과 시간을 표시하고, 보내기 버튼이 중단 버튼으로
  바뀝니다. 중단하면 연결을 끊고 입력한 메시지를 입력칸에 되돌립니다.

일반 파일 첨부와 여러 대화 목록은 아직 제공하지 않습니다.

## v0.6.0 개선

- 글 강화기와 사이드 채팅을 한 창으로 합쳤습니다.
- 답변을 스트리밍으로 받아 쓰는 대로 보여 줍니다(OpenAI Responses·Gemini SSE).
- 근거 문장에 출처 링크와 번호를 붙이고, 누르면 출처 확인 창을 거쳐 엽니다.
- 답변 끝 제어 블록으로 요청을 `앱 조작`·`웹 조사`·`글 상담`으로 분류합니다.
- 검색어·출처 기록을 후속 질문에 넘겨 같은 검색을 줄입니다.

- 외부 자료가 섞인 대화의 기능 명령을 지우는 대신 적용 확인 카드로 바꿨습니다.
- 답변 진행 표시, 경과 시간, 중단 버튼을 추가했습니다.

- 사이드 채팅에 현재 글 강화기 작업 컨텍스트와 기능 명령 브리지를 연결했습니다.
- 첨부 선택·화면 촬영·음성 입력·기억 승인처럼 사용자 확인이 필요한 기능은

- 메인 화면과 사이드 채팅의 `다시 강화`는 이전 출력·질문·AI 추론을 제외하고
  원문과 기존 설정으로 새 결과 버전을 만듭니다.
- 현재 상황과 직접 지정한 문체·구조·목적을 기본 규칙보다 우선하고, 구체적인
  분량 요구는 강화 범위보다 먼저 적용합니다. 사용자 제공 정보 밖의 이름·날짜·
  수치·장소·관계·확정 여부는 새 사실로 추정하지 않습니다.

## v0.4.1 개선

- 후속 입력 안내를 `아니면 다른 요구 사항 입력`으로 변경했습니다.
- 사이드 채팅 초기화 직후 입력 가능 상태와 포커스를 두 차례 복구합니다.

## 사용 흐름

- 첫 화면에는 글 입력과 강화 범위만 보입니다. `상황`과 `도구`는 필요할 때만
  작은 버튼으로 펼칩니다.
- 선택 사항인 `상황`에 수신자나 작업 맥락을 짧게 적습니다.
- 본문은 맞춤법이나 순서를 신경 쓰지 않고 입력합니다.
- 접힌 `도구`에서 파일, 화면 촬영, 말하기를 꺼냅니다. 이미지, PDF, TXT,
  Markdown, CSV, JSON을 최대 4개까지 참고 자료로 붙일 수
  있습니다. 파일 하나는 8MB, 전체는 12MB 이하이며 텍스트는 파일당 2만 자,
  전체 5만 자까지만 모델에 전달합니다. PNG·JPEG·WebP·GIF·PDF는 실제 파일
  헤더까지 확인해 확장자만 바꾼 위장 파일을 모델 호출 전에 차단합니다.
- `화면 촬영`은 강화기 창을 숨기고 잠시 기다린 다음 현재 모니터를 촬영하며,
  성공·실패와 관계없이 원래 창 상태를 복원합니다.
- 바로 결과를 원하면 `완성하기`, AI가 꼭 필요한 질문 하나를 먼저 하게 하려면
  `알아맞춰 봐`를 누릅니다.
- `강화 범위`는 5단계입니다. 중앙 `원문 충실`은 맞춤법과 구조를 중심으로
  원문 분량의 약 90~110%를 목표로 합니다. 왼쪽은 45~85%의 요약·정리,
  오른쪽은 120~200%의 내용 보완·확장으로 실제 목표 글자 수가 달라집니다.
- 결과는 원문과 기존 설정으로 `다시 강화`할 수 있고 `이전`·`다음`으로 모든
  버전을 오갈 수 있습니다. `예`나 직접 요구 반영은 현재 결과를 이어 다듬습니다.
- `강화한 글 복사`는 결과를 클립보드에 복사하고 패널을 접습니다.
- 답변도 여러 줄로 적거나 마이크 버튼으로 말할 수 있습니다. Chromium 음성
  인식이 제공되지 않거나 권한·네트워크 문제가 있으면 원인을 안내하고
  Windows 음성 입력 `Win+H`를 대안으로 표시합니다.

## 로컬 보관과 제어

- 상황, 입력, 답변, 사전 질문, 결과 버전과 첨부는 임시 저장되어 재시작 뒤
  복원됩니다. 첨부 바이너리는 별도 캐시에 저장되며 일반 타이핑 자동 저장 때
  다시 쓰지 않습니다.
- 히스토리는 최대 40개 작업과 작업당 최대 12개 결과 버전을 로컬에 보관합니다.
  목록에서 처음 입력한 원문과 결과를 함께 확인하고, 각 항목을 독립적으로
  불러오거나 삭제할 수 있습니다.
- 기억은 최대 50개, 요청당 관련 기억은 최대 5개만 사용합니다. 설정에서
  저장된 기억을 직접 확인·수정·삭제할 수 있습니다.
- 새 기억 후보는 결과 뒤에 먼저 보여 주며 `기억에 추가`를 명시적으로 누른
  경우에만 저장합니다. `기억 추가 비활성화`를 켜면 새 기억을 만들지 않되
  기존 기억은 유지합니다.
- 모델이 `explicit` 또는 `repeated`라고 주장해도 사용자 입력에 실제 영속
  선호 단서와 내용 근거가 없으면 임시 추론으로 강등합니다. 첨부 자료의 지시가
  장기 기억이 되지 않습니다.

## 창 설정

상단 제목 부분, 팝업 제목, 접힌 손잡이를 드래그해 창을 옮길 수 있습니다.
오른쪽 아래 `↘` 손잡이로 창 크기를 조절할 수 있으며 자유 이동 모드에서는
다시 잡을 수 있는 가장자리만 남기고 창 일부를 화면 밖에도 둘 수 있습니다.
설정에서:

- 좌우 화면 가장자리에 붙는 `고정`과 어디에나 놓는 `자유 이동`
- 투명도 55~100%
- 글자 크기 85~130%
- 창 너비 380~680, 높이 560~920

를 조절합니다. 화면 관련 조절은 변경 즉시 적용·저장되며 별도 취소 단계가
없습니다. 입력과 버튼은 드래그 표면이 아니므로 정상 선택·클릭할 수 있습니다.
모니터 추가·제거 또는 배율·작업 영역 변경이 감지되면 창을 즉시 보이는 화면
안으로 재배치합니다.

## 검증과 패키징

```powershell
npm.cmd test
npm.cmd run screenshot
npm.cmd run dist
npm.cmd run smoke
```

- `test`: 저장 한도, 멀티모달 payload, Gemini 스키마/크기, 기억 근거,
  캡처 복원 순서, 드래그·음성 UI 계약을 검사합니다.
- `screenshot`: `qa/v3-*.png`에 입력, 접힌/펼친 도구, 질문 우선,
  결과/버전, 기억 승인, 원문·결과 히스토리, 설정, 기억 편집, 최소 투명도
  화면을 만들고 `qa/v4-01-side-chat-beta.png`에 연동 채팅 화면,
  `qa/v4-02-first-follow-up.png`에 개선된 첫 질문,
  `qa/v4-03-side-chat-edit.png`에 메시지 수정 화면,
  `qa/v5-01`~`v5-04`에 적용 확인 카드·진행 표시·출처 확인 창·답변 스트리밍을 만듭니다.
- `dist`: `dist/Writing-Enhancer-<버전>-portable.zip`을 만듭니다.
- `smoke`: 압축과 실행 파일을 확인한 뒤 패키지 앱을 실제로 띄워 렌더러 준비
  상태와 창 숨김 화면 촬영·복원을 검사하고 `dist/smoke-report.json`에 결과를
  기록합니다. 또한 ZIP을 새 임시 폴더에 실제로 풀고 그 안의 실행 파일도
  `--smoke-test`로 직접 부팅한 뒤 임시 파일을 삭제합니다.

기본 `dist`는 Electron 실행 파일의 바이트를 수정하지 않고 이름만 바꾼 뒤
`resources/app`에 앱을 배치합니다. 이 PC의 Application Control에서
electron-builder가 수정한 실행 파일은 차단됐지만 이 정책 호환 패키지는 직접
실행 스모크가 통과했습니다. 비교용 builder 결과가 필요할 때만
`npm.cmd run dist:builder`를 사용합니다. 정식 배포 전에는 별도의 코드 서명
인증서를 적용하는 것이 좋습니다.
